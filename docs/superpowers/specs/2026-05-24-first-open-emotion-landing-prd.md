# 首次打开 App 场景 MVP 低保真 PRD

## 1. 场景定义

本文聚焦的不是完整 AI 陪伴产品，而是用户首次打开 App 时的第一条核心体验链路。

目标场景为：

- 用户第一次进入 App
- 用户此刻有情绪，但不一定想清楚了怎么说
- 用户更需要先被接住、被安放，而不是立刻进入深度聊天

这一版的产品定位不是“会聊天的 AI”，而是：

`帮助用户用最低门槛完成一次情绪落地、安抚与收好的首次体验。`

## 2. 产品目标

本场景需要完成 5 件事：

1. 降低首次表达门槛，让用户不用一上来打很多字
2. 帮用户先靠近自己的状态，而不是要求准确描述情绪
3. 在识别后给出一条轻而准的共情承接
4. 用动态场景延长安全停留，而不是立刻推进流程
5. 给这次体验一个私密、安静、可确认的收尾

## 3. 非目标

MVP 明确不做以下内容：

- 正式自由聊天主链路
- 长文本倾诉入口
- 多轮复杂追问
- 多场景并行分支
- 复杂情绪分析报告
- 强建议、强解决方案、说教式干预
- 多人可见或公开分享机制

## 4. MVP 核心定义

当前 MVP 的核心不是“聊起来”，而是走通这条首次体验闭环：

`被接住 -> 被理解 -> 被安放 -> 被收好`

对应页面链路为：

1. 极速破冰
2. 隐性感知识别
3. 极致共情回应
4. 视觉治愈与转化
5. 留白沉淀与隐私封存

## 5. 反推后的最小闭环

基于当前五张图，首次打开场景的最小闭环可先定义为：

1. 用户完成一次 `天气标签 + 文字标签` 的低门槛情绪上报
2. 系统返回一份可确认、可调整的初步情绪画像
3. 系统给出一条基于标签组合的共情回应
4. 用户在动态疗愈场景中停留一段时间
5. 用户完成一次“封存今天”，并看到已封存卡片

这意味着 MVP 的完成标准不是“用户开聊了”，而是“用户完整经历了一次被理解和被收住的情绪安放流程”。

## 6. 页面流程说明

### 6.1 第一步：极速破冰

**页面目标**

让用户在不打很多字的前提下，完成第一次情绪汇报。

**核心判断**

首屏不以自由输入为主，而以轻触式选择为主。

**页面元素**

- 场景氛围图，承担进入感和陪伴感
- 天气选择区，采用滑动或横向切换方式
- 文字标签区，展示若干低门槛口头表达
- 可选说明文案，强调“不用先打很多字”

**用户动作**

- 选择 1 个最接近当下感受的天气标签
- 选择 1 个最接近自己的文字标签

**系统处理**

- 记录天气标签
- 记录文字标签
- 形成一组初始情绪线索，供下一步识别使用

**完成条件**

用户已完成至少 `1 个天气标签 + 1 个文字标签` 的选择。

**转场逻辑**

完成选择后进入“隐性感知识别”页。

### 6.2 第二步：隐性感知识别

**页面目标**

基于前一步的线索，帮助用户从模糊感受靠近更具体的情绪状态。

**核心判断**

这一页不是下结论，而是给出一份“初步猜测，可确认、可调整”的情绪画像。

**页面元素**

- 已选天气标签回显
- 已选文字标签回显
- 粗粒度情绪层，例如 `烦躁 / 低落`
- 细粒度情绪层，例如 `委屈 / 防备 / 不被理解`
- 用户语气说明，强调“你不用说得很准，我们先帮你靠近它”

**用户动作**

- 浏览识别结果
- 确认结果大体符合当前状态
- 如有必要，可轻量调整标签或重新返回上一步

**系统处理**

- 基于天气标签、文字标签和预设映射关系生成粗粒度与细粒度情绪结果
- 输出一份用于共情回应生成的中间态情绪画像

**完成条件**

用户确认当前识别结果可进入下一步。

**转场逻辑**

进入“极致共情回应”页。

**文案建议**

当前如不立即进入聊天，主按钮不建议写成“开始聊聊”，建议改为：

- `嗯，就是这种感觉`
- `是这样的，继续`
- `先这样，往下走`

### 6.3 第三步：极致共情回应

**页面目标**

给用户一条足够轻、足够准、不造成压力的安抚回应。

**核心判断**

这一步不是正式聊天，而是一次基于前面标签组合自动生成的共情承接。

**页面元素**

- 共情角色或陪伴体形象
- 一条主回应气泡
- 语气说明标签，例如 `朋友式回应 / 不分析 / 不说教`
- 可选的轻说明区，解释“这句话没有建议，只是想先接住你”

**用户动作**

- 阅读回应
- 感受是否被接住

**系统处理**

- 采用 `规则骨架 + 轻生成` 方式输出文案
- 规则骨架负责稳定方向
- 轻生成负责自然化语言、降低模板感

**话术生成输入**

- 天气标签
- 文字标签
- 粗粒度情绪
- 细粒度情绪

**完成条件**

用户已收到一条与当前状态匹配的安抚回应。

**转场逻辑**

进入“视觉治愈与转化”页。

### 6.4 第四步：视觉治愈与转化

**页面目标**

把上一步的一句安抚，延展成一个可停留的感官陪伴空间。

**核心判断**

这是一个“自动启动的可停留陪伴场景页”。

- 进入页面后自动播放
- 不催促用户立刻离开
- 允许用户在场景内停留更久

**页面元素**

- 火焰从无到有的动态变化
- 背景环境由冷到暖的视觉转化
- 雨声、篝火声等背景音
- 轻量的停留型按钮，例如 `再待一会`

**用户动作**

- 观看动态场景
- 听背景音
- 主动选择继续停留

**系统处理**

- 自动触发动态渲染和背景音播放
- 在第一轮渲染后进入稳定陪伴态
- 当用户点击 `再待一会` 后，触发一次更深的安抚反馈

**点击“再待一会”后的变化**

- 场景进一步变暖，例如火更旺、灯更亮、雨声更柔
- 出现更轻的陪伴动作或在场提示

**停留抓手**

- 以视觉变化为主
- 以听觉氛围为辅
- 以轻交互延长停留
- 不以新增文案为主承载

**完成条件**

用户在场景中完成一段自然停留，并准备收口。

**转场逻辑**

从陪伴场景轻过渡到“留白沉淀与隐私封存”页。

### 6.5 第五步：留白沉淀与隐私封存

**页面目标**

让这次被接住、被安放的体验有一个私密、明确、安静的结束动作。

**核心判断**

这一页是首次体验的默认收尾，不是可有可无的附加页。

**页面元素**

- 一句简短留白输入，可写可不写
- “仅你可见 / 只属于你 / 安心保留”等隐私提示
- 主按钮 `封存今天`

**用户动作**

- 浏览封存说明
- 可选输入一句留白
- 点击 `封存今天`

**系统处理**

- 保存本次体验的摘要信息
- 生成一张已封存卡片

**封存内容范围**

- 天气标签
- 文字标签
- 粗粒度情绪结果
- 细粒度情绪结果
- 当前场景快照
- 可选的一句自留文字

**完成条件**

用户已完成封存动作。

**转场逻辑**

进入“已封存卡片”结果页。

## 7. 已封存卡片页说明

当前版本建议采用 `情绪摘要卡` 方案，而不是更重的“给未来自己的信”方案。

**页面目标**

让用户明确感知：这一刻已经被私密、妥帖地收好了。

**页面元素**

- 已封存状态确认
- 天气标签摘要
- 情绪标签或识别结果摘要
- 场景快照
- 返回首页按钮

**当前版本定位**

- 先做摘要卡
- 不强化纪念感
- 不展开长期回看体系

**后续可扩展方向**

- 向“给未来自己的小卡片”演进
- 增强留白感和纪念感

## 8. 功能逻辑说明

### 8.1 标签输入策略

- 首次打开时，用户主输入方式为轻触选择
- 天气标签负责外化情绪气候
- 文字标签负责低门槛口头表达
- 两类标签组合后，形成后续识别与回应的基础输入

#### 8.1.1 前台与后台标签分层

当前标签量适合作为后台映射底表，不适合原样前台展示。

建议分为三层：

- `前台首开发现层`：用户在首屏真正看到并可直接点击的少量标签
- `映射识别层`：用于从天气和口头表达推断粗粒度、细粒度情绪
- `扩展词库层`：更多同义词、近义口头禅和后续可扩充表达

产品原则：

- 首页不要平铺全部标签
- 首页只解决“轻轻开口”，不解决“完整表达”
- 后台可以复杂，前台必须简单

#### 8.1.2 首开页标签结构建议

MVP 建议首开页采用 `1 个天气 + 1 个状态词 + 可选 1 个需求词` 的结构。

其中：

- `天气` 是必选，用来帮助用户先选一个外部情绪气候
- `状态词` 是必选，用来表达“我现在怎么了”
- `需求词` 是可选，用来表达“我希望别人怎么对我”

不建议首屏把状态词和需求词完全混在一起等权展示。

#### 8.1.3 首开页前台展示数量建议

为了降低决策压力，建议首屏可见数量控制如下：

- 天气标签：`4 个`
- 当前天气对应的状态词：`4 个`
- 可选需求词：`2-4 个`

也就是说，用户在一个时间点上看到的主要决策量最好控制在 `8-10` 个以内。

#### 8.1.4 天气首发清单建议

首版建议保留 4 个天气入口：

1. `大暴雨`
2. `起大雾`
3. `阴天乌云`
4. `大雪深夜`

选择理由：

- 四个天气的情绪区分度较高
- 都容易形成场景感和后续视觉映射
- 能覆盖烦躁、迷茫、委屈、疲惫这几类高频首开状态

#### 8.1.5 每个天气对应的首开可见状态词建议

以下词建议作为首开页第一层可见状态词，而不是一次性把后台全量词库全部展示出来。

`大暴雨`

- `烦死了`
- `真的会谢`
- `心态崩了`
- `太难了`

`起大雾`

- `好焦虑`
- `尽力了`
- `没动力`
- `让我呆一会`

`阴天乌云`

- `无语`
- `心累`
- `不想说话`
- `别管我`

`大雪深夜`

- `彻底累了`
- `一片空白`
- `难受`
- `想躲起来`

#### 8.1.6 状态词与需求词拆分建议

从体验上看，当前词库里混合了两类表达：

`状态词`

- 烦死了
- 好焦虑
- 心累
- 难受
- 一片空白

`需求词`

- 让我呆一会
- 不想说话
- 别管我
- 想躲起来

建议：

- 首开页优先展示状态词
- 需求词作为可选补充，不作为第一步的主决策
- 如需继续细化，可在用户选完状态词后再出现“要不要再补一个词”

#### 8.1.7 与后续识别的连接方式

标签输入后的推荐链路为：

`天气 -> 状态词 -> 可选需求词 -> 粗粒度 Mood -> 细粒度 Emotion -> 共情回应 -> 场景转化`

这意味着首页不是在做“情绪诊断”，而是在给后续识别和安抚提供第一手线索。

### 8.2 识别策略

- 当前版本优先使用规则映射
- 先输出粗粒度 Mood
- 再输出细粒度 Emotion
- 用户看到的是“靠近式识别”，不是强判断结论

### 8.3 共情话术策略

- 当前版本采用 `规则骨架 + 轻生成`
- 骨架控制语义方向和安全边界
- 轻生成控制自然度和去模板感
- 回应语气以朋友式承接为主，不分析、不说教、不解决

### 8.4 动态场景策略

- 进入第四阶段后自动播放，不需要用户手动触发
- 自动播放后进入稳定态，允许用户停留
- 用户主动点击“再待一会”后，页面应给出二次安抚反馈，而不是简单重复

### 8.5 封存策略

- 封存动作是一次情绪收口，不是任务完成提示
- 重点强化“仅你可见”的安全感
- 当前版本只需完成摘要封存，不必展开复杂卡片体系

## 9. 体验原则

整条链路需要统一遵守以下原则：

1. 先接住，再靠近，再收好
2. 降低输入压力，不要求用户先讲清楚
3. 不做强判断，不替用户定义自己
4. 不急着给建议，不把安抚做成指导
5. 尽量用氛围、节奏和轻反馈延长停留
6. 让结束动作有安全感，而不是任务感

## 10. MVP 版本边界

当前版本建议只做一套完整场景：

- 单一主场景：雨夜篝火营地
- 单一主链路：首次打开完整闭环
- 单一收尾形式：封存今天 + 已封存摘要卡

当前版本不建议扩张到：

- 多场景并行
- 长对话链路
- 多角色陪伴人设
- 复杂情绪报告
- 社交化沉淀分享

## 11. 当前待后续一起确认的点

以下内容可在下一轮继续细化：

- 每一步的主按钮文案定稿
- 可选需求词是否在首版就展示
- 识别映射关系是否需要人工校对表
- 第三步共情话术的首版模板数量
- 第四步停留时长与自动过渡节奏
- 第五步摘要卡的视觉字段优先级

## 12. 对齐标注页口径的功能说明

这一节用于对齐当前站点 `标注 PRD 克隆页` 的写法，统一采用 `显示内容 / 交互 / 功能` 三段式描述。

### 12.1 页面一：极速破冰

**显示内容**

- 场景氛围图
- 天气选择滑杆或天气标签带
- 文字标签区
- 低门槛说明文案

**交互**

- 用户滑动或点击天气标签
- 用户点击一个文字标签
- 选中状态即时回显

**功能**

- 承接首次打开时的轻量表达入口
- 让用户先用低成本动作完成一次情绪上报
- 为下一步情绪识别提供基础输入

### 12.2 页面二：隐性感知识别

**显示内容**

- 已选天气标签
- 已选文字标签
- 粗粒度情绪结果
- 细粒度情绪结果
- 可确认、可调整的语气说明

**交互**

- 用户查看系统给出的初步情绪画像
- 用户确认当前结果是否大体符合
- 如不符合，可返回上一步重新选择

**功能**

- 将模糊输入转化为更可感知的情绪状态
- 帮用户从“说不清”过渡到“先靠近”
- 为共情回应提供结构化情绪中间态

### 12.3 页面三：极致共情回应

**显示内容**

- AI 陪伴体或朋友式角色
- 一条共情回应气泡
- 语气说明标签，例如 `不分析 / 不说教 / 不解决`

**交互**

- 用户阅读回应
- 用户感受是否被接住
- 页面自动进入下一步场景陪伴

**功能**

- 基于标签组合返回一条安抚话术
- 让用户先获得“被看到”的感觉
- 把识别结果转化为情绪承接，而不是技术反馈

### 12.4 页面四：视觉治愈与转化

**显示内容**

- 从无到有的火焰动态
- 由冷到暖的场景变化
- 雨声、篝火声等背景音
- `再待一会` 之类的轻停留按钮

**交互**

- 页面进入后自动播放
- 用户可停留观看和聆听
- 用户点击 `再待一会` 后触发更深一层的安抚反馈

**功能**

- 用感官氛围延长停留时间
- 把“一句安抚”转化为“一段陪伴”
- 让用户在安全环境中慢慢缓下来

### 12.5 页面五：留白沉淀与隐私封存

**显示内容**

- 一句可选留白输入
- 隐私说明标签
- `封存今天` 主按钮

**交互**

- 用户可写可不写
- 用户点击 `封存今天`
- 页面进入已封存结果卡

**功能**

- 给整段首次体验一个安静的结束动作
- 让当下情绪被私密地收住
- 把体验结果沉淀为可查看的摘要卡

### 12.6 已封存卡片页

**显示内容**

- 已封存状态确认
- 天气摘要
- 情绪摘要
- 场景快照
- 返回首页按钮

**交互**

- 用户查看封存结果
- 用户点击返回首页，结束首次体验

**功能**

- 明确告知用户“这一刻已经被收好”
- 给封存动作一个可见结果
- 作为首次体验的最终收尾页

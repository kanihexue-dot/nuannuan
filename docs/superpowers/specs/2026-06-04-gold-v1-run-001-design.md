# Gold v1 与 run_001 执行设计

## 目标
- 用固定 50 条题库先跑出一轮 `run_001` 模型回复。
- 从 `run_001` 结果中挑出 `30` 条，构成 `gold_v1`。
- 用 `gold_v1` 校准 grader，而不是直接扩整套评测系统。

## run_001 最小结果表
结果表保留以下字段：
- `run_id`
- `测评ID`
- `主场景`
- `子场景`
- `用户输入`
- `模型回复`
- `粗筛标签`
- `粗筛理由`
- `是否入选_gold_v1`
- `整体可用性`
- `朋友感`
- `情绪承接`
- `短回复与少建议`
- `证据句`

## 粗筛标签
仅使用四类：
- `明显可用`
- `明显不可用`
- `轻边界`
- `不选`

粗筛最短口径：
- 像朋友 + 接住了 + 没乱教 = `明显可用`
- 像老师 + 没接住 + 很会教 = `明显不可用`
- 大方向没翻车但有一点拿捏空间 = `轻边界`
- 太重复 / 太模糊 / 没价值 = `不选`

## gold_v1 结构
- 规模：`30` 条
- 来源：同一版回复器输出
- 覆盖：`10` 个主场景 × 每个 `3` 条
- 场景内结构：`2` 条明显样本 + `1` 条轻边界样本

## human gold 标注字段
- `整体可用性`：`可用 / 不可用`
- `朋友感`：`1 / 3 / 5`
- `情绪承接`：`1 / 3 / 5`
- `短回复与少建议`：`1 / 3 / 5`
- `证据句`

## 软否决规则
任一关键维度为 `1`，则整体默认 `不可用`。

## 执行顺序
1. 固定一版回复器输出。
2. 跑出 `run_001` 的 50 条模型回复。
3. 将 50 条结果写入结果表。
4. 对 50 条结果做粗筛。
5. 从中挑出 30 条形成 `gold_v1`。
6. 对 30 条打 human gold。
7. 后续用 `gold_v1` 校准 grader。

## 暂不纳入本阶段
- 不全量标 8 个维度。
- 不做 grader 微调训练。
- 不做完整 AlignEval 平台化重构。

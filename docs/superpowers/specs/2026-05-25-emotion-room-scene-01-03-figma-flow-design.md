# 小情绪房间 01-03 串联交互页 Figma 设计规格

## 1. 背景

当前项目里已经有一套基于 `1.png` 到 `5.png` 的五步情绪场景页，但这次要单独抽出一条更适合演示和讲解的交互路径，用于在 Figma 中设计和串联原型。

这条新路径不覆盖现有五步总览页，而是从中提取最关键的两段体验：

- `第一场景`：`01 极速破冰`
- `第三场景`：`03 极致共情回应`

中间的 `02 隐性感知识别` 不单独扩展成完整大页面，而是作为 `01 -> 03` 之间的一次短暂识别过渡出现。

## 2. 设计目标

这条串联交互页需要同时完成 4 件事：

1. 让业务方看到一次完整且清晰的体验路径
2. 让 `01` 的轻量进入和 `03` 的情绪承接都被完整保住
3. 让 `02` 作为“识别翻译机制”被看见，但不抢主舞台
4. 让 Figma 原型具备清晰的状态帧和连线，不是 2 张静态图拼接

## 3. 非目标

这一版明确不做：

- 完整五步流程全部串成一个大原型
- 真正的聊天会话流
- 复杂输入表单
- 守护轨 `L0-L3` 的独立展示
- 多分支交互

这一版的重点是：`01 的进入动作 -> 02 的识别过渡 -> 03 的共情回应落点`

## 4. 推荐方案

采用 `A 方案`：做成一个 `01 -> 03` 的串联交互页，而不是两个独立页面。

推荐原因：

- 更适合讲“用户怎么从输入走到被接住”
- 第一和第三场景可以放在同一世界观里连续推进
- 比两张独立页面更像真正的 UX 路径
- 也更方便在 Figma 中做 5 帧状态原型

## 5. 页面结构

页面使用一个横版桌面框架，但核心视觉重心在左侧的大竖版场景卡上。

### 5.1 顶部区

顶部保留一条简化后的流程提示，用于表达体验顺序：

- `01 极速破冰`
- `02 识别过渡`
- `03 极致共情回应`

这里不是完整五步导航，而是当前串联体验的路径条。

### 5.2 左侧主舞台

左侧为视觉核心，使用大尺寸竖版卡片承载主要场景。

- `01` 使用第一张场景图
- `03` 使用第三张场景图
- `02` 沿用第一张场景图，加识别浮层，不另开独立大图

主舞台要尽量保住现有竖版稿的构图和氛围，不把信息拆得太碎。

### 5.3 右侧说明区

右侧为讲解信息区，跟随当前状态切换内容。

右侧承担的内容包括：

- 当前步骤标题
- 一句话摘要
- 关键词标签
- 当前阶段的讲解重点
- 示例输入 / 示例回应 / 识别结果

右侧说明区的职责是帮讲解者说清楚，不与左侧主场景争主视觉。

### 5.4 底部区

底部只保留轻量操作，不再展示安全轨。

可出现的操作包括：

- `继续进入回应`
- `继续`

操作数量应控制在最少，避免打断讲解节奏。

## 6. 交互路径

这条原型的交互节奏为：

1. 用户进入 `01 极速破冰`
2. 选择一个天气
3. 选择一句最接近当前情绪的话
4. 点击继续，进入 `02` 的识别过渡
5. 短暂显示“输入 -> 情绪识别”的翻译过程
6. 过渡到 `03 极致共情回应`
7. AI 朋友回应分两段出现

交互原则：

- 只保留少量高确定性交互
- 让状态变化服务讲解，不做自由探索式复杂操作
- 每一步只有一个主要动作

## 7. 五个状态帧

Figma 中建议把这一页拆成 `5` 个连续状态帧。

### 7.1 `F01_01_default`

内容：

- 主舞台显示 `1.png`
- 默认高亮 `大暴雨`
- 口头禅区未确认
- 右侧说明强调“低门槛进入”
- 底部 `继续` 按钮禁用

### 7.2 `F02_01_selected`

内容：

- 主舞台仍显示 `1.png`
- `天气 + 口头禅` 都已经选中
- 继续按钮变为可点击
- 右侧补充“这一步不要求用户立刻讲清楚”

### 7.3 `F03_02_mapping`

内容：

- 主舞台仍沿用 `1.png`
- 整体压暗一点
- 中间浮出半透明识别卡
- 卡片内容展示：
  - 天气
  - 口头禅
  - 粗粒度 Mood
  - 细粒度 Emotion
- 右侧解释识别逻辑

### 7.4 `F04_03_reply_start`

内容：

- 主舞台切换到 `3.png`
- AI 气泡先出现第一段回应
- 右侧说明切成“朋友式回应 / 不分析 / 不说教”
- 底部保留 `继续`

### 7.5 `F05_03_reply_full`

内容：

- 主舞台仍显示 `3.png`
- AI 气泡补出第二段回应
- 右侧显示完整示例回应
- 页面停在“被接住”的落点状态

## 8. 视觉与动效原则

### 8.1 视觉方向

视觉语言要沿用当前项目已经确定下来的方向：

- 紫蓝系主色
- 雨夜营地场景氛围
- 左侧主舞台尽量保住竖版稿
- 右侧说明区保持明亮、可讲、克制

### 8.2 动效方向

推荐动效：

- 选择状态：轻微浮起 + 高亮
- `01 -> 02`：识别卡淡入
- `02 -> 03`：主图柔和切换
- `03` 气泡：分段出现

避免：

- 大幅翻转
- 炫技式位移
- 游戏化过强的反馈

## 9. Figma 组织方式

### 9.1 页面

建议创建一个专门页面：

- `Emotion Room / 01-03 Flow`

### 9.2 主状态帧命名

- `F01_01_default`
- `F02_01_selected`
- `F03_02_mapping`
- `F04_03_reply_start`
- `F05_03_reply_full`

### 9.3 每帧图层结构

建议统一图层顺序：

1. `Top Progress`
2. `Stage Card`
3. `Right Notes`
4. `Bottom Action`

`Stage Card` 继续拆为：

- `Stage Background`
- `Scene Image`
- `Scene Overlay`
- `Recognition Card` 或 `AI Bubble`
- `Local Chips`

### 9.4 建议抽成组件

- `Step Tab`
- `Weather Chip`
- `Tag Button`
- `Primary CTA`
- `Info Block`

## 10. 原型连线建议

- `F01 -> F02`
  - 触发：点击口头禅
  - 动效：`Smart Animate / 250ms / Ease Out`

- `F02 -> F03`
  - 触发：点击 `继续进入回应`
  - 动效：`Dissolve + Smart Animate / 300ms`

- `F03 -> F04`
  - 触发：点击识别卡继续，或自动延时
  - 动效：`Smart Animate / 320ms`

- `F04 -> F05`
  - 触发：点击 `继续`
  - 动效：`Smart Animate / 220ms`

原型原则：

- 框架不变，状态变化
- 保持同一类元素命名一致
- 尽量通过透明度、位置、文本和高亮状态来完成过渡

## 11. 验收标准

如果这条串联交互页成立，应该满足：

1. 业务方能一眼看出体验是从 `01` 走到 `03`
2. `01` 的动作门槛足够低
3. `02` 的识别逻辑被看见，但不会打断节奏
4. `03` 的回应有“先接住”的感受
5. Figma 原型切换看起来像一次交互推进，而不是几张图硬切
